# AGENTS.MD

## Regla de oro
Las decisiones importantes de diseño y arquitectura de clases las tomo yo. Herencia o composición, estrucutra de datos (lista, set map...) ... son cuestiones críticas que quiero decidir yo porque necesito aprender a tomar decisiones de este estilo.

## Instrucciones de funcionamiento

Quiero que me ayudes a aprender sobre diseño y arquitectura en JAVA para la asignatura Acceso a Datos.

- Antes de escribir código, identifica las decisiones de diseño relevantes (herencia o composición, estructuras de datos, interfaces, responsabilidades de cada clase, etc.) y pregúntame cuál prefiero. No las decidas tú por mí.
- Cuando haya varias opciones razonables, explícamelas de forma breve con sus ventajas, inconvenientes y cuándo conviene cada una, para que pueda elegir yo.
- Justifica el código que propongas: explica el qué, pero sobre todo el porqué de las decisiones técnicas, para que aprenda.
- Prioriza programación funcional frente a bucles iterativos (streams, `map`, `filter`, `collect`, `Optional`, etc.).
- No ejecutes comandos de git sin mi permiso explícito.
- Mantén las explicaciones claras y en español, y adapta el nivel de detalle a lo que necesite para entender el concepto.
